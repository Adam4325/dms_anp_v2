1. PENJELASAN MENGAPA LOG PER DO BISA > 20 KALI (BUKAN HANYA 6 KALI)
--------------------------------------------------------------------------------
Secara alur bisnis Logkar, tahapan status DO terdiri dari 6 status utama:
  - 3  : Menuju Lokasi Muat
  - 4  : Tiba di Muat
  - 12 : Selesai Muat
  - 5  : Menuju Bongkar
  - 6  : Tiba di Bongkar
  - 99 : Pesanan Selesai

Namun pada Log Monitoring tercatat hingga 20+ baris per DO karena:

a. Satu Kali Aksi Menghasilkan Multi-Log (2 - 3 Event):
   Setiap kali aplikasi driver mengirimkan 1 status, sistem backend mencatat:
   1) "Driver App Request" : Request masuk dari HP driver (Android Sync).
   2) "Lookup DO ID"       : Server ANP memanggil API Logkar (/orders/do/get)
                             untuk mencari do_id berdasarkan do_no.
   3) "Status Order"       : Server ANP memanggil API Logkar (/transporter/status/order).
   Saat penyelesaian order, ada aksi "Upload Docs (POD)" yang juga melakukan
   Lookup DO ID + multipart upload gambar POD.
   Sehingga hitungan normal: 6 status x 2-3 log + Upload POD = 15 s/d 18 log.

b. Driver Menekan Tombol Berulang Kali (Multiple Tap / Retry):
   Pada beberapa DO (misal R32083126), tercatat "Driver App Request" beruntun
   dalam selisih hitungan detik (contoh: 05:59:02, 05:59:07, 05:59:12, 05:59:16, 05:59:24).
   Hal ini terjadi karena koneksi lambat atau tidak ada loading disable pada tombol,
   sehingga driver menekan tombol berulang kali.

c. Pengiriman Longitude / Latitude:
   Setiap request status order (3, 4, 12, 5, 6, 99) WAJIB menyertakan koordinat
   latitude & longitude driver saat tombol ditekan.
   Selain itu, pada aplikasi mobile ada background service
   (LogkarPositionBackgroundService) yang mengirim posisi secara berkala (per 1 menit)
   ke endpoint /transporter/order/position.

3. BREAKDOWN DAN PENYEBAB ERROR (345 KEGAGALAN)
--------------------------------------------------------------------------------

[1] BUG PARSING ANGKA DESIMAL / QTY PECAHAN (51x GAGAL)
    - Pesan Error: {"error":"For input string: \"6.5\""}
      (terjadi juga pada nilai "5.5", "3.5", "2.5", "2.55")
    - Lokasi Kode : trucking/web/mobile/api/do_mixer/update_status_do_mixerv2.jsp (baris 525-526)
    - Penyebab    :
      Muatan unit mixer beton berupa volume m3 sering bernilai desimal (6.5 m3, 5.5 m3, dst).
      Kode backend memanggil:
          loadingQty = Integer.parseInt(rows.get(0).toString());
          reduceQty = Integer.parseInt(rows.get(1).toString());
      Fungsi Java Integer.parseInt() otomatis crash (NumberFormatException) saat membaca
      string yang memiliki titik desimal ("6.5").
    - Akibat      :
      Pengiriman status ke Logkar langsung GAGAL TOTAL dan masuk ke blok catch (kategori OTHER).
      Status DO di Logkar tidak ter-update sama sekali.

[2] LOGKAR 400165: INVALID DO STATUS (153x GAGAL - ERROR TERBESAR)
    - Pesan Error: {"status":"invalid do status"} (Code 400165)
    - Penyebab    :
      API Logkar menerapkan state machine urutan status yang ketat:
      3 -> 4 -> 12 -> 5 -> 6 -> 99.
      Jika driver melompat status atau status sebelumnya (misal status 12/5) GAGAL
      terkirim akibat bug desimal di atas, status DO di Logkar masih tertahan di status lama.
      Saat driver menekan tahap berikutnya (misal Status 6 atau 99), Logkar menolak
      dengan error 400165 "invalid do status".
      Juga terjadi jika driver menekan tombol status yang sama berulang kali setelah status
      tersebut sudah sukses di Logkar.

[3] LOGKAR: DO_ID NOT FOUND / LOOKUP EMPTY (124x GAGAL)
    - Pesan Error: {"error":"do_id not found for do_no=R58023177"}
                   {"status":"OK","data":[],"code":200}
    - Contoh DO   : R58023177, R28094899
    - Penyebab    :
      Nomor DO tersebut belum didaftarkan / belum ter-create / belum di-dispatch
      di sistem Logkar oleh tim Shipper/Logistik. Saat backend mencari ke /orders/do/get,
      Logkar mengembalikan array kosong "data": [].
    - Akibat      :
      Karena do_id tidak ada, semua aksi pengiriman status maupun upload POD untuk
      DO tersebut dipastikan gagal.

[4] LOGKAR 400166: DO ALREADY COMPLETED (13x GAGAL)
    - Pesan Error: {"status":"do already completed"} (Code 400166)
    - Contoh DO   : R32083138, R01162024
    - Penyebab    :
      DO sudah berstatus 99 (Selesai), namun aplikasi driver atau retry mencoba
      mengirimkan status lagi (misal Status 6 atau status lainnya). Logkar menolak
      karena DO yang sudah closed tidak bisa menerima perubahan status.

[5] ERROR DOKUMEN & FOTO POD (2x GAGAL)
    - Pesan Error: {"status":"invalid file size"}
                   {"status":"Document not exists"}
    - Penyebab    :
      File foto bukti DO / POD di server memiliki ukuran tidak valid (terlalu kecil/kosong)
      atau status 99 dipanggil sebelum dokumen POD terupload dengan benar.
